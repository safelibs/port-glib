# Implementation Plan: Port GLib 2.80.0 From C to Rust

## 1. Context

The goal is to turn the upstream GLib 2.80.0 codebase in `original/` into a Rust implementation in `safe/` that is source-compatible, link-compatible, runtime-compatible, and package-compatible on Ubuntu 24.04.

This repository is not starting from zero. The current `safe/` tree already contains:

- A Cargo workspace in `safe/Cargo.toml` with crates for `glib`, `gthread`, `gmodule`, `gobject`, `gio`, `girepository`, and `abi-support`.
- A Meson bootstrap wrapper in `safe/meson.build` and a Debian package build path in `safe/debian/rules`.
- Frozen upstream source and build artifacts in `safe/vendor/original` and `safe/vendor/build-check`.
- ABI, symbol, layout, package, and test manifests in `safe/abi/`.
- Editable upstream test mirrors in `safe/tests/upstream/`.
- CVE regression probes in `safe/tests/cve/`.
- Packaging smoke tests in `safe/tests/package/`.

The current safe implementation is a hybrid bootstrap, not a finished Rust port:

- `safe/crates/glib` already owns selected ABI exports in Rust, especially CVE-sensitive entry points:
  - `safe/crates/glib/src/hash/api.rs:396-970`
  - `safe/crates/glib/src/gvariant/api.rs:229-280`
  - `safe/crates/glib/src/markup/api.rs:57-184`
  - `safe/crates/glib/src/charset/api.rs:82-144`
  - `safe/crates/glib/src/spawn/api.rs:140-316`
  - `safe/crates/glib/src/bytes/api.rs:11-20`
  - `safe/crates/glib/src/fileutils/api.rs:65-71`
  - `safe/crates/glib/src/keyfile/api.rs:18-36`
- `safe/crates/glib/build.rs` still links a replayed upstream backend generated by `safe/tools/build-glib-backend.py`. That script currently rewrites 96 frozen GLib compile commands and renames the backend symbols (`safe/tools/build-glib-backend.py:11-276`).
- `safe/crates/gthread/build.rs` and `safe/crates/gmodule/build.rs` still inject upstream object files directly from `safe/vendor/build-check`.
- `safe/crates/gio/build.rs` still injects upstream `gio` objects and archives directly from `safe/vendor/build-check/gio`.
- `safe/tools/build-abi-shell.py` still seeds each build root from `safe/vendor/build-check`, rebuilds only a subset of helper binaries, and still fabricates vendored static archives for `gthread`, `gmodule`, `gio`, and `girepository` when `static_objects` / `static_archives` are present in its library table.
- `safe/crates/gobject` is mostly translated Rust under `safe/crates/gobject/src/translated/original/gobject/*.rs` and compiles, but `cargo check --workspace` currently emits many warnings and the repository-wide unsafe audit script still fails.
- `safe/crates/girepository/src/exports.rs` still exports 229 placeholder symbols plus 2 real exports, with only minimal real runtime functions in `safe/crates/girepository/src/runtime.rs:10-18` and those two real exports around `safe/crates/girepository/src/exports.rs:466-485`.
- `test-original.sh` is still an original-GLib harness. It builds upstream into `/opt/glib-original`, asserts binaries load the original library (`test-original.sh:60`), builds the original tree (`test-original.sh:119`), installs dependents (`test-original.sh:152`), and runs package-specific runtime probes (`test-original.sh:481-549`). It does not yet build or install the `safe/` Debian packages.
- `safe/debian/tests/control` already defines the Debian package test surface: `build`, `build-static`, `installed-tests`, `closure-refcount`, `debugcontroller`, `gdbus-server-auth`, `gdbus-threading`, `gmenumodel`, `mainloop`, `memory-monitor-dbus`, `socket`, `testfilemonitor`, `thread-pool-slow`, `threadtests`, `timeout`, `timer`, and `1065022-futureproofing`. The current harness does not yet execute those scripts against `safe/` packages.

Upstream scope is large, so the workflow must follow real subsystem boundaries:

- Upstream export counts from `safe/abi/version-scripts/*.map`:
  - `libglib-2.0.so.0`: 1872 symbols
  - `libgthread-2.0.so.0`: 2 symbols
  - `libgmodule-2.0.so.0`: 10 symbols
  - `libgobject-2.0.so.0`: 478 symbols
  - `libgio-2.0.so.0`: 2107 symbols
  - `libgirepository-2.0.so.0`: 231 symbols
- Frozen test manifests in `safe/tests/manifests/`:
  - `glib-core.txt`: 83 rows
  - `glib-advanced.txt`: 68 rows
  - `gobject.txt`: 62 rows
  - `gio.txt`: 133 rows
  - `girepository.txt`: 11 rows
  - `fuzzing.txt`: 22 rows
  - `full.txt`: 384 rows

The implementation strategy should use the existing hybrid bootstrap only as an oracle and compatibility scaffold. The final result must retire direct linkage to upstream object files, vendored static-archive construction, and shipped helper/tool artifacts copied from `safe/vendor/build-check`, while preserving the current ABI/package/test artifact machinery as the verification backbone.

## 2. Generated Workflow Contract

The generated workflow derived from this plan must obey these fixed rules:

- Linear execution only. Do not use `parallel_groups`.
- Emit self-contained inline YAML only. Do not use top-level `include`, and do not use phase-level `prompt_file`, `workflow_file`, `workflow_dir`, `checks`, or any other YAML-source indirection.
- Do not use agent-guided `bounce_targets` lists. Every verifier must use one fixed `bounce_target`.
- Every verifier must be an explicit top-level `check` phase.
- Every verifier must stay in the implementation block it verifies and must bounce only to that implementation phase.
- If a verifier needs to run tests, lint, build, package, or any other command, those commands must be written into the checker instructions; do not model them as separate non-agentic phases.
- The workflow must consume the existing artifacts in place. It must not refetch, rediscover, or regenerate the upstream source snapshot or the frozen metadata from scratch unless a phase is explicitly updating those files in place.
- The workflow must preserve the consume-existing-artifacts contract for:
  - `original/`
  - `dependents.json`
  - `relevant_cves.json`
  - `safe/vendor/original/`
  - `safe/vendor/build-check/`
  - `safe/abi/`
  - `safe/tests/manifests/`
  - `safe/tests/upstream/`
  - `safe/debian/`
  - `safe/docs/cve-matrix.md`
  - `safe/docs/debian-patch-provenance.md`
  - `test-original.sh`
- The workflow must treat `safe/vendor/original/` and `safe/vendor/build-check/` as authoritative read-only oracles unless a phase explicitly changes the frozen-artifact contract in place.
- The workflow must preserve the current “editable upstream mirror” model for `safe/tests/upstream/*`; later phases must update those files in place instead of replacing them with a fresh sync.
- Each implement phase must produce at least one new git commit before yielding to its listed verifiers. A checker must treat an unchanged `HEAD` or a worktree-only deliverable as a failure.
- Every implement prompt in the generated workflow must instruct the agent to commit work to git before yielding.
- Each major implementation phase below must be emitted as one implement phase followed only by the listed check phases; later workflow generation must not invent extra topology.

## 5. Final Verification

After all phases complete, the implementation should be considered done only if the following full-system verification passes:

1. Metadata and contract verification
   ```bash
   cd safe
   cargo check --workspace
   python3 tools/extract_abi.py --verify
   python3 tools/extract_layouts.py --verify
   python3 tools/link-compat.py --verify-manifests
   python3 tools/verify-debian-patches.py --verify-manifest
   ```

2. Final build-root verification
   ```bash
   cd safe
   python3 tools/build-abi-shell.py --build-root build-final --multiarch "$(dpkg-architecture -qDEB_HOST_MULTIARCH)" --stamp build-final/.stamp
   python3 tools/link-compat.py --phase full --build-root build-final --compile-original-objects --run
   python3 tools/run-meson-manifest.py --build-root build-final --baseline abi/tests.json --path-map abi/test-source-path-map.json --intro-tests build-final/meson-info/intro-tests.json --manifest tests/manifests/full.txt --print-errorlogs
   python3 tools/run-cve-regressions.py --all --build-root build-final --rebuild
   python3 tools/compare-layouts.py --build-root build-final --baseline abi/layouts/glib.json --baseline abi/layouts/gthread.json --baseline abi/layouts/gmodule.json --baseline abi/layouts/gobject.json --baseline abi/layouts/gio.json --baseline abi/layouts/girepository.json
   ```

3. Exported symbol verification
   ```bash
   cd safe
   for pair in \
     "abi/symbols/libglib-2.0.so.0.symbols build-final/glib/libglib-2.0.so.0.8000.0" \
     "abi/symbols/libgthread-2.0.so.0.symbols build-final/gthread/libgthread-2.0.so.0.8000.0" \
     "abi/symbols/libgmodule-2.0.so.0.symbols build-final/gmodule/libgmodule-2.0.so.0.8000.0" \
     "abi/symbols/libgobject-2.0.so.0.symbols build-final/gobject/libgobject-2.0.so.0.8000.0" \
     "abi/symbols/libgio-2.0.so.0.symbols build-final/gio/libgio-2.0.so.0.8000.0" \
     "abi/symbols/libgirepository-2.0.so.0.symbols build-final/girepository/libgirepository-2.0.so.0.8000.0"; do \
       set -- $pair; \
       python3 tools/compare-symbols.py --expected "$1" --library "$2"; \
     done
   ```

4. Package verification
   ```bash
   cd safe
   dpkg-buildpackage -b -uc -us
   python3 tools/compare-debian-control.py --baseline abi/debian-control-preservation.json --control debian/control
   python3 tools/verify-package-baselines.py --source . --work-root build-package-baselines-final --abi-shell-profiles "nodoc noinsttest nogir noudeb" --install-manifests abi/install-manifests --postinst-manifest abi/postinst-state/runtime.json
   ```

5. Installed-package smoke, Debian autopkgtest, and dependent verification
   ```bash
   GLIB_UNDER_TEST=safe GLIB_TEST_SCOPE=all ./test-original.sh
   ```

6. Final safety and cleanup verification
   ```bash
   cd safe
   python3 tools/check-unsafe-audit.py
   ! rg -n "PLACEHOLDER_" crates/girepository/src/exports.rs
   ! rg -n "vendor/build-check" crates/*/build.rs
   ! rg -n "build-glib-backend.py" crates/glib/build.rs
   ! rg -n "SAFE_VENDOR_BUILD_CHECK|vendor/build-check" tools/stage-package-tree.py
   ! rg -n "static_objects|static_archives|build_vendored_static_archive" tools/build-abi-shell.py
   ```

The implementation is not complete if any library still depends on linked upstream object files for its shipped runtime, if any shipped static archive or helper executable still comes from `safe/vendor/build-check`, if any placeholder export remains, if the safe packages fail to replace the original packages in the `package-smoke`, `debian-tests`, or `dependents` harness scopes, or if the final unsafe audit still flags avoidable unsafe code.
